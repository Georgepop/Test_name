## 🎯 Описание проекта

Проект решает задачу **маршрутизации парка карьерных самосвалов** в условиях:
- Разнородного дорожного покрытия (асфальт, гравий, грунт);
- Рельефа местности с подъёмами и спусками;
- Ограниченной пропускной способности дорог и пунктов погрузки/разгрузки.

**Входные данные:**
- Граф карьерной сети (14 вершин, 36 рёбер);
- Парк из 20 самосвалов трёх моделей;
- Физические параметры (координаты, длины, уклоны).

**Выходные данные:**
- Оптимальный маршрут для каждого самосвала;
- Расписание движения (время старта, проезда, обслуживания);
- Визуализация графа с маршрутами;
- JSON-отчёт `result.json`.

## 🛠 Технологии

### 3.1. Основной стек

| Технология | Версия | Назначение | Обоснование выбора |
| :--- | :---: | :--- | :--- |
| **Python** | 3.8+ | Основной язык | Широкая экосистема для OR, научные вычисления |
| **Google OR-Tools** | ≥9.5 | CP-SAT решатель | Лидер в области constraint programming, открытый код |
| **NetworkX** | ≥2.6 | Работа с графами | Стандарт де-факто для графов в Python |
| **Matplotlib** | ≥3.4 | Визуализация | Гибкость, интеграция с Jupyter |
| **pytest** | ≥7.0 | Тестирование | Простота, фикстуры, параметризация |

### 3.2. Почему CP-SAT, а не MILP?

Задача маршрутизации с ограничениями пропускной способности и очередями естественным образом формулируется на языке **ограничений (constraints)**, а не линейных неравенств:

| Аспект | MILP (Gurobi/CPLEX) | CP-SAT (OR-Tools) |
| :--- | :--- | :--- |
| Очереди и ресурсы | Требует big-M трюков | Нативный `AddCumulative` |
| Логические условия | Сложно | `OnlyEnforceIf`, булевы переменные |
| Нелинейные функции | Требуют линеаризации | Поддержка `AddElement`, таблиц |
| Скорость на комбинаторных задачах | Средняя | Высокая (Multi-core, LNS) |

### 3.3. Альтернативы (для расширения)

- **PuLP / Pyomo** — для MILP-подхода;
- **Ray / Dask** — для распределённых вычислений;
- **Gurobi / CPLEX** — коммерческие MILP-решатели;
- **Stable Baselines3** — если переходить к RL-подходу.

## 📦 Установка

### 4.1. Системные требования

- **ОС**: Linux (Ubuntu 20.04+), macOS 11+, Windows 10+
- **Python**: 3.8 – 3.11
- **RAM**: минимум 4 ГБ (для 20 самосвалов), 8+ ГБ для больших парков
- **Make**: GNU Make 3.81+ (для `Makefile`)

### 4.2. Пошаговая установка

#### Шаг 1. Клонирование
```bash
git clone https://github.com/your-repo/truck-routing.git
cd truck-routing
```

#### Шаг 2. Виртуальное окружение
```bash
# Linux / macOS
python3 -m venv venv
source venv/bin/activate

# Windows (PowerShell)
python -m venv venv
.\venv\Scripts\Activate.ps1
```

#### Шаг 3. Установка зависимостей
```bash
pip install --upgrade pip
pip install ortools==9.7.2996 networkx==3.1 matplotlib==3.7.2 pytest==7.4.0
```

#### Шаг 4. Проверка установки
```bash
python -c "from ortools.sat.python import cp_model; import networkx; print('OK')"
```

Должно вывести: `OK`

### 4.3. Troubleshooting

| Проблема | Решение |
| :--- | :--- |
| `ModuleNotFoundError: ortools` | `pip install ortools` |
| Ошибка компиляции matplotlib | Установить системные зависимости: `sudo apt install python3-tk` |
| `make: command not found` | Windows: установить [Chocolatey](https://chocolatey.org/) → `choco install make` |
| Конфликт версий Python | Использовать `pyenv` или `conda` |

### 4.4. Установка через Conda (альтернатива)
```bash
conda create -n truck-routing python=3.10
conda activate truck-routing
conda install -c conda-forge ortools networkx matplotlib pytest
```

## 🐍 Запуск прототипа (Standalone)

Файл `1o.py` — автономный прототип со всеми этапами решения.

```bash
python evaluate.py
```

**Что делает:**
1. Строит граф карьера из встроенных данных;
2. Генерирует парк из 20 самосвалов;
3. Рассчитывает физические параметры (уклоны, скорости);
4. Генерирует кандидаты маршрутов;
5. Решает CP-SAT модель (8 потоков, 120 сек);
6. Выводит результаты в консоль;
7. Открывает визуализацию графа;
8. Сохраняет `result.json`.

## 📁 Структура проекта

**`Data.py`**
Содержит данные и физические модели:
- `DATA` — узлы, рёбра, парк самосвалов
- `ROAD_TYPES` — типы дорог и их параметры
- `build_graph()` — построение NetworkX DiGraph
- `create_trucks()` — генерация парка машин
- `travel_ticks()` — расчёт времени проезда с учётом уклона и покрытия
- `get_candidate_paths()` — поиск альтернативных путей
- `get_full_routes()` — формирование полных маршрутов (Start → Load → Dump)

**`baseline_.py`**
Реализует решатель на базе CP-SAT:
- `TruckRoutingModel` — класс CP-SAT модели
- `build()` — создание переменных и ограничений
- `solve()` — запуск решателя OR-Tools
- `extract_solution()` — извлечение и парсинг маршрутов
- *Точка входа для команды `make baseline`*

**`evaluate.py`**
Отвечает за анализ качества решения:
- `evaluate_solution()` — расчёт метрик (makespan, утилизация, простои) на основе `result.json`
- Формирование и вывод отчёта в консоль/файл
- *Точка входа для команды `make eval`*

**`make_animated.py`**
Визуализация результатов:
- `visualize_graph()` — статичная отрисовка графа с маршрутами
- `animate_schedule()` — анимация движения самосвалов по графу
- *Точка входа для отображения графа*

**`result.json`**
- Файл с результатами работы модели (список маршрутов `paths` и время завершения `times`).
